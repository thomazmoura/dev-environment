# NeoVim configuration

`~/.config/nvim` → `modules/nvim-config/`. Edits take effect in the next NeoVim started.

## Layout

| Path | What lives there |
|---|---|
| `init.lua` | Entry point. Sets the leader (Space), requires `config.*`, then lazy |
| `lua/config/` | Options, filetypes, commands, autocmds, `keymaps/` (`common.lua` is shared with VS Code), clipboard (`"+` is the clipboard of the device typing, decided per copy/paste from the tmux client in front by `front_client.lua`: local, `wl-copy`/`wl-paste`; another machine over ssh or a link, OSC 52 out and `tmux refresh-client -l <pane>` back, read as a TermResponse; Termux, the phone's clipboard through `termux_clipboard.lua`, sockets ssh forwards back to `termux-clipboard-get`/`set`, set up by `Termux/termux-setup.sh` and `LinuxDevEnv/sshd-setup.sh`), `paste_image.lua` (`<Leader>p` in markdown buffers pastes a clipboard image as a saved file plus a Markdown image link), `cmdline_normal.lua` (normal mode in the command line), `pane_background.lua` and `ssh_title.lua` (tmux integration), `zoom.lua` (tmux-like zoom of the window: `<Leader>z` the same buffer in a 90% float that closes when left, `<Leader>Z` alone in a tab with the tabline hidden; either key zooms back out, handing the cursor back), `dadbod_locksmith.lua` (dadbod's SQL Server and Postgres passwords in locksmith, unlocked first; `<Leader>db` opens DBUI only once it is), `dbout_compact.lua` (lays out SQL Server results from sqlcmd's separator-split output, framed and split into columns by extmarks over unchanged text: line breaks as ↵, long values cut on screen, `yic` yanking the whole value via `after/ftplugin/dbout.lua`), `dbout_cell.lua` (`<Leader><CR>` in results shows the whole cell in a read-only popup: JSON indented, HTML also opened in the browser with paperboy's no-scripts policy), `dbout_move.lua` (`H`/`L` in results move to the previous/next cell of the row, from the dash line's runs as display columns), `dbout_pin.lua` (a float of the same buffer keeps a SQL Server result's header and dash line at the top of the window while its rows scroll, as Workhorse's build log header does, following the horizontal scroll and wrapping, and keeping the cursor off the rows it covers), `sql_dialect.lua` (which SQL language servers a sql buffer gets), `sql_connection.lua` (connects the SQL Server servers to the buffer's dadbod database: SqlToolsService with `connection/connect`, so hover shows column types and `gd` opens a table's or view's CREATE script, which inherits the connection, and sqlserver-assist with `sqlserver/connection`, a SqlClient connection string; the password goes over their stdin only, and not at all while the LSP log level is DEBUG, where `lsp.log` would get it), `sql_statement.lua` (`<Leader>r` in a sql buffer runs only the statement under the cursor, `<Leader>R` the buffer; the statement comes from sqlserver-assist's `sqlserver/statements`, ScriptDom's parse, or from `sql_split_postgres.lua`, psql's own `;` rules in Lua), `sql_completion_triggers.lua` (where blink's menu opens on a space, after a join's ON, and on a `(`, after `INSERT [INTO] <table>`, for sqlserver-assist's completions; blocked elsewhere), `bare_path.lua` (blink's path source, completing paths without a leading `./`), `dadbod_fuzzy.lua` (blink's dadbod source, handing blink every table/column for the context so it filters fuzzily instead of by prefix), `dotnet_debug/` (.NET debugging on nvim-dap/netcoredbg: `<Leader>dr` the buffer's project, attaching to its `dotnet watch` app when there is one, `<Leader>dR` a picked project, `<Leader>dt` the test or test class under the cursor through Roslyn's `textDocument/runTests`, and `display.lua`, which shows Guid, DateTime and co. as an evaluated `ToString()` instead of `{System.Guid}`, by type, overridable from `plugins/debug.lua`, and `completion.lua`, blink's `dap_roslyn` provider completing the Watches pane and the dap REPL from Roslyn as if typed on a new line after the stopped statement, through a temporary `didChange` the buffer never sees; its `README.md` has how each works), `dap_session_keys.lua` (while a dap session runs, each `<Leader>d{key}` is also `<M-{key}>`, taken from Harpoon and given back when it ends, and `gH`/`<CR>` open the value under the cursor in a popup as dap-ui's expandable tree) |
| `autoload/sqlserver_locksmith.vim`, `autoload/postgresql_locksmith.vim` | vim-dadbod's sqlserver and postgresql adapters (`g:db_adapter_sqlserver`/`g:db_adapter_postgresql` point to them): dadbod's own, with the password filled in by `config/dadbod_locksmith.lua` |
| `lua/config/lazy.lua` | lazy.nvim setup. `defaults.cond = not vim.g.vscode`. `dev.path = ~/code` for `thomazmoura/*` plugins (falls back to GitHub) |
| `lua/plugins/<domain>.lua` | One file per domain: `ai`, `colorscheme`, `completion`, `database`, `debug`, `editor`, `git`, `lsp`, `paperboy`, `personal`, `telescope`, `tmux`, `treesitter`, `ui` |
| `lazy-lock.json` | Pinned versions. Commit it after `:Lazy update`/`sync`. Setup runs `Lazy! restore` |
| `after/ftplugin/`, `snippets/` | Per-filetype tweaks, VS Code-format snippets |
| `lua/vscode-profile/` | Keymaps/commands used instead of plugins when `vim.g.vscode` |
| `notes.lua` | The **Notes pane** profile (`nvim -u ~/.config/nvim/notes.lua`, tmux `prefix,n`) |

`modules/vim/` holds data only (spell files, swap), behind `~/.local/share/nvim/site`. It has no config.

## Conventions

- **A plugin's keymaps go in its spec's `keys`**, and its setup in `opts`/`config`, inside the matching domain file. General keymaps go in `lua/config/keymaps/`.
- **A spec loads under VS Code only with `cond = true`.**
- **The Notes pane is deliberately minimal:** `loadplugins = false`, and it adds only vim-tmux-navigator, auto-save.nvim and markview.nvim from the full config's lazy install via its `add()`. It has no status bar, a transparent background, and treats `.notes` as markdown. Changes asked "for the Notes pane" go in `notes.lua`, not the full config.
- **Personal plugins** are in `lua/plugins/personal.lua` (workhorse.nvim for Azure DevOps, spotlight-dimmer) and `lua/plugins/paperboy.lua` (paperboy.nvim, the Exchange inbox, with its e-mail signature in `compose.signature_file`). They load from `~/code/<plugin>` when present, so changes to the plugin itself belong in that repo. Paperboy loads only when `$PAPERBOY_EWS_URL` is set. Both keep their secrets (PAT, Exchange password, cache keys) in **locksmith.nvim** (`~/code/locksmith.nvim`), one encrypted store unlocked with a password asked once per NeoVim (`:Locksmith`, `bin/locksmith` on the command line). Dadbod keeps its SQL Server and Postgres passwords there too (namespace `dadbod`, one per scheme, server and login), saved once the server accepted them.
- **LSP servers** are configured in `lua/plugins/lsp.lua` (`vim.lsp.enable`, `node_server(...)` for npm ones). Installers are in `modules/neovim-lsp/`; the `deploy` skill has the recipe. The SQL servers (`sqlserver_ls`, `sqlserver_assist`, `postgres_lsp`) share the sql filetype, so they stay out of `vim.lsp.enable`: `config/sql_dialect.lua` starts a dialect's servers per buffer, from a pin (`:SqlDialect`, `<Leader>dm`/`dp`/`da`), the dadbod connection, or the syntax. `sqlserver_assist` is our own server, built from `modules/sql-assist` (its README has the protocol): "Expand *" and "Toggle ;" in `<Leader>.`'s code actions (`<Leader>;` toggles the statement's `;`, `<Leader>:` all of them, in place of the command history while it is attached), join conditions and INSERT column lists in the completion (blink's `sql_assist` provider; the other SQL servers' completion is turned off), and `<Leader>r`'s statements. After changing its C#, run `modules/sql-assist/Build-SqlAssist.ps1` and `:lsp restart`. Roslyn (roslyn.nvim) is started directly, not through its thin client's shared daemon, so it gets `--extensionLogDirectory`, which `<Leader>dt`'s test runs need; the roslyn client's `handlers` answer `workspace/attachDebugger` for them.
- **NeoVim usually runs through pwsh** (tmux panes use `pwsh_invocation`) so the profile's environment and `Use-NodeVersion` apply. Copilot and node-based servers rely on that.

## Verifying

```bash
nvim --headless "+qa"                                         # full config loads without errors
nvim --headless -u modules/nvim-config/notes.lua "+qa"        # Notes profile
nvim --headless "+Lazy! restore" +qa                          # after editing lazy-lock.json
```
